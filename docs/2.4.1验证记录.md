# 2.4.1 性能与内存优化验证

2026-10-13，本地性能优化交付。比较基线为 `fe0ec21` 对应的 2.4.0；本次不创建标签、不推送、不发布 GitHub Release。

## 保持的行为

- STEP/OBJ 内容、AD/KiCad 图形、原始尺寸、模型放置规则、符号/封装配套引用保持原有语义。
- 3D 坐标在传输中保持 IEEE 双精度，仍由同一 WebGL 程序计算法线并最终上传单精度顶点。材质、光照、相机和鼠标操作不变。
- 每次批量下载仍刷新官方资源。新缓存仅在一次导出内存在，最多 32 MiB、256 项；并行相同请求合并，缺失或失败结果不长期缓存，等待者仍可取消。
- 登录 Cookie 独立保存在各会话中，沿用原有 Cookie、重定向和代理切换行为。商城连接复用不自动重试 POST 或收藏操作。
- 图片保持原始分辨率供查看。解码移入后台，原图缓存按解码像素限制为 32 MiB；大收藏列表按视口预取，每张表最多保留 128 个缩略图。
- 商城账号仍在启动后恢复，完整商城控件首次使用时创建。备份页在显示时后台扫描，关闭程序仍等待正在执行的工作结束。
- 所有自生成数据继续保存在 LOCALAPPDATA 下的 LCSC3D 目录；验证使用隔离配置，不访问真实登录会话。

## 实现

收藏图片更新不再触发整表勾选统计；进度使用带补偿的累计和，避免每次扫描整个批次。模型资源、放置基准、AD 校验/压缩与 KiCad 压缩结果在批次内复用。3D 预览采用连续双精度顶点缓冲区及后台编码，JavaScript 直接写入浮点缓冲区，收到绘制成功回执后释放 Python 传输数据。下载响应使用连续缓冲区，避免同时保留分块列表和拼接副本。

商城沿用 urllib 的 Cookie/重定向处理，底层通过现有 urllib3 连接池发送请求。消息筛选复用未变化的表格项和搜索文本。打包移除只由 PDF 图片插件使用的 QtPdf 运行库，保留 WebEngine、QtQuick/QtQml、SVG/常用图片插件和软件 OpenGL 回退。

## 验证范围

专项回归覆盖批次缓存的新鲜度、并发去重、失败重试、取消及容量限制；重复模型保留不同放置并只写入一个资源；双精度传输与旧接口一致；真实 WebGL 新旧传输的画布像素一致；收藏视口图片和内存限制；代理切换、Cookie 隔离、重定向、重复 Cookie 头、POST 不重试；备份扫描期间界面响应和关闭等待。

性能原始材料和成品验收保存在已忽略的 `work/optimization-20261013/`。合成模型采用 30 万顶点、10 万三角面；Python 分配统计不含输入 OBJ、浏览器及 GPU，不能视为整机内存增量。JavaScript 微基准在 Node/V8 中执行真实查看器代码并核对上传缓冲区，不包含 GPU 绘制或 Qt IPC。网络连接实验仅访问本机 HTTP 服务。

## 本机测量

| 项目 | 2.4.0 基线 | 2.4.1 | 条件 |
| --- | ---: | ---: | --- |
| 1,000 行收藏表更新 20 张缩略图 | 197.978 ms | 1.062 ms | 同进程交替 5 轮；不含网络/绘制 |
| 10,000 个器件各 10 次进度更新 | 7,623.194 ms | 125.299 ms | 3 轮中位数；不含下载/界面接收 |
| 10 万三角面 Python 处理峰值 | 93,824,057 B | 57,775,753 B | tracemalloc；不含输入 OBJ/浏览器/GPU |
| 10 万三角面查看器准备 | 300.968 ms | 221.981 ms | Node/V8 交替 5 轮；上传缓冲区 SHA-256 一致 |
| 商城连续 4 次 GET 的 TCP 连接数 | 4 | 1 | 本机 HTTP/1.1；Cookie 隔离另有回归 |
| EXE 大小 | 148,525,685 B | 146,056,291 B | 141.65 → 139.29 MiB |
| 单文件归档解压内容 | 354,560,675 B | 349,923,723 B | 保留 WebEngine 依赖和软件 OpenGL |
| EXE 到主窗口可见 | 2.654 s | 2.614 s | 交替 3 轮中位数；每轮空配置，未清 OS 文件缓存 |

启动耗时基本持平，不据此宣称明显提速。后台模型准备、JavaScript、网络和渲染属于不同阶段，表中微基准不可相加推算真实下载总时长或整机物理内存变化。模型峰值降低约 38.4%；原始样本和逐轮数值分别保存在 `core-comparison.json`、`thumbnail-comparison.json`、`viewer-comparison.json`、`startup-comparison.json`。

实际 Qt/WebGL 大模型验收成功：30 万顶点、10 万面均正确到达渲染器，约 1.90 秒进入 ready；处理期间界面定时器继续执行，绘制回执后 Python 传输数据释放。PNG、JPEG、WebP、带 EXIF 旋转的 JPEG、SVG 的新旧图片解码结果逐像素一致。该项材料为 `large-preview-verification.json`，不属于网络性能测量。

## 最终回归与成品

- 最终源码 **650 项全量测试通过，257.582 秒**；构建前完成验证，构建日志为 `build.txt`。
- 真实 WebGL 的旧网格接口与新紧凑传输画布像素一致；大模型、材质、多边形、退化面和精度边界的上传缓冲区另作比对。
- 冻结 EXE 的 9 组模型导出验收通过，6.80 秒，覆盖 AD/KiCad、合并、独立副本、无模型和无效参数；保留 Type-C 固定位置断言和内嵌原始 STEP 校验。
- 冻结 EXE 进度/消息验收通过，5.17 秒，包含日志打包、清除后继续写入及消息历史保留。
- 冻结 EXE 商城、设置和备份验收分别通过，7.33 / 59.36 / 8.34 秒；登录和短信使用本机模拟服务，不读取真实会话。
- 新连接层另以空会话完成真实 HTTPS 匿名商城查询、商品详情和原图下载：C2040 返回搜索结果及 1426 × 1426 原图，未使用已保存会话。
- 系统 PATH 下的真实匿名下载和 3D/SVG 预览通过，10.8 秒；C2040、C20197 输出 STEP/OBJ，未选择器件不下载，无效编号正确失败，主窗口句柄保持不变，查看器页面复用。
- 空配置启动和旧配置迁移通过，EXE 旁和当前工作目录未产生应用数据，既有标记文件保留。
- 实际 **2.4.0 → 2.4.1** 本机 HTTP 更新验证通过，11.41 秒；使用不同版本的真实 EXE，完成下载、SHA-256 校验、助手替换、重启与回执，保留设置。
- EXE 的 **73 个模块、36 项资源**与工作区一致；无 CAD 运行库。PDF 图像插件及 QtPdf 已移除，QtQuick/QtQml 和软件 OpenGL 仍保留。
