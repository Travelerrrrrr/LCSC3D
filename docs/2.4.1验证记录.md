# 2.4.1 数据手册、购物车与订单验证

功能验证日期：2026-10-13；发行核对日期：2026-10-14。发行以 `codex/bug-fix` 的应用代码为准。

## 数据手册原因与修复

在未登录的公开商品页复现了 C2861386、C507270、C34678、C74511、C69527 的手册缺失。商城把手册放在 `productRecord.fileTypeVOList` 的 `pdf_property` 分组中，TI 商品使用 `linkAddress` 厂商链接；旧实现仅读取 `pdfFileDetailVO.fileUrl`，且商城页成功时未从 EDA 目录补充手册。

现在按手册分组读取厂商链接及商城 PDF 路径，保留旧字段兼容；不把认证或行业通知作为手册。商城页缺少手册时补用 EDA 目录链接。五个器件实网重查分别得到 TLV757P（两个封装）、TPS723、LP2985、LM2776 的 TI 数据手册。对应公开字段已裁剪成离线回归样本，不含账号或 Cookie。

## 本次修复与交互调整

用户反馈旧“快捷下单”打开外部浏览器后提示“订单数据已过期”。旧逻辑在软件会话中调用 `/async/validate/perfect`，随后只打开固定的订单确认地址；原自动测试仅验证接口成功和打开地址，未验证跨会话的结算数据。商城公开订单页面在数据接口返回 303 时显示该提示。

按用户确认的新要求，按钮改为 **跳转到购物车**，直接调用系统默认浏览器打开 `https://cart.szlcsc.com/cart/display.html`。移除结算提交函数、后台任务及订单确认地址；打开按钮不修改数量或网页勾选状态，空购物车、未勾选和软件未登录也可以打开。浏览器未打开时提示重试，重试只打开页面。

搜索、收藏和原生购物车表格增加 **递增量**。数量加减遵循器件步长，手动输入在确认或离开输入框时向上取整为满足起订量及步长的数量；右键加购会先提交尚在编辑的输入。数量在搜索、收藏与下载列表之间同步，购物车修改仍经过合并请求后保存，并按商城包装比例转换。

搜索页 **单价 / 梯度** 自动显示当前数量的价格，展开可查看全部价格区间；查看另一个区间不会改变实际数量对应的单价。翻页和重复搜索同一器件保留数量及对应报价。价格计算在本地进行，不增加网络请求，缺失报价显示“—”。数量、递增量和单价在表格中相邻显示。

## 接口依据与公开数据核验

未登录读取 C2861386 和 C20197 的公开搜索结果，确认递增量分别为 5 和 50；整盘包装量分别为 3000 和 5000，不作为递增步长。商城的 `theRatio` / `convesionRatio` 用于步长和组数换算；搜索起订量及价格梯度门槛转换为实际件数，避免将 50 件一组的报价门槛显示成 1 件。

参考商城公开 [购物车脚本](https://static.szlcsc.com/cart/_next/static/chunks/pages/cart/display-b803df0005a56902.js)、[商品详情脚本入口](https://item.szlcsc.com/3066063.html) 和 [订单公共工具脚本](https://static.szlcsc.com/order/_next/static/chunks/2363-b03f38c940868ac8.js)。开发过程中未读取真实用户 Cookie、订单或地址。

自动账号操作使用本地服务与合成数据；浏览器启动使用桩核对固定商城地址和调用次数，未创建订单或付款。用户在外部浏览器登录自己的账号并确认网页购物车内容。

## 日志检查

`store.purchase_quantity` 记录数量与递增量，`cart.quantity`、`cart.add` 覆盖写请求及异常；`commerce.external_open` 区分系统浏览器启动成功与失败。删除已无对应行为的 `cart.checkout` / `cart.checkout_prepared` 路径。价格匹配不访问网络。

只记录器件编号、数量、计数、操作类型及错误类型，不记录购物车键、订单号、正文、地址或凭据。隔离 LOCALAPPDATA 验证日志打包、清除和清除后继续记录；异常钩子、崩溃诊断与轮转保持既有覆盖。

## 批量加购补充修复（2026-10-13）

用户日志记录 C20618009 加购 1 个时 HTTP 200、业务码 402，账号校验已通过；随后整批提前返回，C5832372 没有发送。公开 [C20618009 商品页](https://item.szlcsc.com/21993682.html) 标记“商品已停售”。另行查询 C5832372 的公开商品资料，确认起订量和递增量均为 20，截图中的收藏页却显示 1；这是收藏规则未完整带入造成的第二个问题。

- 提取批量服务，明确的 402 业务拒绝和本地数量/停售校验失败继续后续器件。超时、未知服务错误、部分成功响应或登录失效停止；每项至多发送一次，不自动重试，保留前面已成功的结果。
- 搜索、收藏和详情保留商城停售状态；停售信息优先展示于型号前。库存为零本身不等于停售，保留海外商品与可售在途库存的区别。
- 收藏保留接口自带的购买规则；缺失规则显示“—”，加购前只核实勾选器件，并缓存结果。原数量 1 不符合新取得的 20 起订时，先更新表格并提示确认，不发送数量 1 或暗中加购 20；再次确认加购才发送 20。
- 界面区分成功、失败、未确认、未发送，显示器件编号和原因；“查看结果”打开消息页的完整逐项明细。成功项取消加购勾选，失败项保留，减少重复加购。
- 日志新增逐项结果、是否尝试发送、业务码、原因分类、规则核实、停止原因和界面呈现事件。未知 402 不推断具体原因，诊断不记录任意响应原文、Cookie、账号资料或请求正文。

自动验证使用合成账号及本地服务复现拒绝和成功，不读取用户真实登录会话、不向真实购物车写入。公开状态核验仅访问未登录商品资料。

## 原生订单明细、购物车预览图与 SchLib 位号

- 点击“我的订单”的表格行，在原来的内容区域切换到原生商品表格。显示商品/型号、封装、购买数量、单价、金额和类别，以及订单总额、商品金额和运费。返回保留页码、筛选、选中行与滚动位置；不重新读取订单列表。商城完整订单的浏览器入口放在明细页内。
- 明细通过官方 `order-api.szlcsc.com/member/order/details` 按所选订单读取，使用 `orderVO` 及深圳、江苏、珠海、香港的商品、订货、海外代购列表；数量和金额直接采用订单记录，不以现价重算。只提取所需字段，不展示或解密收货人资料，也不把订单内容记录到日志。
- 勾选可识别的器件后加入下载列表，按 C 编号去重；非器件物品保留展示但不导入。下载任务忙碌时导入禁用，返回、重新查询和退出账号取消旧明细请求。
- 购物车增加预览图，使用共享缩略图缓存及有上限的并发，按可见行加载；图片失败保留占位，旧响应不能覆盖新行，双击可查看原图。
- AD SchLib 原导出器把 RECORD 34 的 `IsHidden` 固定写成 T。现在改为 F，新导出的元件位号默认显示。用独立 OLE 读取器核验实际落盘 SchLib：嘉立创/AD 两种样式、单元/多单元元件、独立/合并/追加，共 12 个元件记录均可见。未操作 AD 本体进行实机放置。

接口字段参考此前获取的商城公开前端脚本 `member/order/details-b251c923b16f0d16.js` 和 `6802-8e320b3ceadf77ba.js`。账号流程使用本地合成服务；未读取真实登录凭据或历史订单。

## 本轮功能与性能优化

- AD SchLib 的 RECORD 41 / Comment 改为显示，与 RECORD 34 / Designator 分行放在符号上方。实际写出并独立解析 8 份 SchLib、12 个元件记录，覆盖嘉立创/AD 两种样式、单元/多单元、独立/合并/追加。KiCad 实际生成的符号库包含两个元件，Reference 与 Value 的 effects 均不含 hide，保持原有默认显示；未操作 AD/KiCad 本体放置。
- 下载列表移除数量列；数量输入保留在搜索、收藏和购物车。搜索和收藏的数量按器件编号索引同步，删除行后使用持久索引定位，避免每次遍历所有行。
- 订单明细增加图片列。响应中有图片地址时直接读取，否则仅为可见器件查询公开目录；复用缓存，双击打开原图。返回订单列表和退出账号会取消旧图片请求。
- 表头增加明暗主题分隔线，数据列可拖动并双击适应内容；用户设定的列宽不会因窗口缩放被覆盖。商品表格两侧布局去掉不对称留白，拖动条位于间距中央。筛选面板在较大字体下可滚动，输入框不被压缩截断。
- 分类树和筛选面板位于原搜索内容区。类别来自官方 `resource-catalog-list-new.json` 的电子元器件目录（仅 MRO 编号的叶节点不冒充元器件分类），分类浏览调用 `/category/product`，关键词筛选调用 `/query/product`，参数候选调用 `/query/param/agg`。筛选含类目、品牌、封装、包装、标签、认证、参数多选/数值范围、现货、折扣、数据手册、品牌来源、排序、价格、需求数量和结果内搜索。
- 已用未登录官方接口实测：STM32F103 配合品牌及 LQFP-48(7x7) 筛选得到 13 项；64KB 参数得到 17 项；64KB–128KB 范围得到 40 项，抽查结果对应的参数与封装正确。数量会随商城库存目录更新，此数据仅记录本次验证。参数编码、多选、分页条件传递和排序通过离线回归检查。
- 先前代码在收藏追加每一行时遍历全表同步数量。本机 1,000 行合成数据、同一套控件回放修改前后同步方法：载入约 0.895 → 0.629 秒；100 次数量同步的三轮中位数约 0.0579 → 0.0082 秒。约 7.1 倍仅指数量同步路径，不代表整个应用速度。
- 搜索、收藏、购物车和订单图片按可见区域及少量缓冲加载，单批最多 20 个地址、最多 3 个并发，缩略图缓存最多 128 张。筛选连续操作合并为 350ms 后一次请求，最近 6 个结果缓存在内存；未改变条件时复用已有搜索候选，分类不在启动时请求。取消和旧响应隔离、稀疏筛选后可见图片、缓存重用均已验证。
- 日志覆盖分类/参数读取、筛选应用与结果数量、任务取消、网络及解析错误、器件图片补查、图片解码失败与导出字段显示。操作上下文与耗时可关联；不写入搜索关键词、筛选值、订单正文或凭据。所有账号、错误和日志清理验证均使用隔离 LOCALAPPDATA 与合成服务。

官方公开前端字段参考：[关键词筛选脚本](https://static.szlcsc.com/so/_next/static/chunks/pages/global-d472945af1e66abe.js)、[分类浏览脚本](https://static.szlcsc.com/list/_next/static/chunks/pages/catalog/%5Bid%5D-23aadfc80ce5daf1.js)、[分类参数控件](https://static.szlcsc.com/list/_next/static/chunks/5310.ba7b0242f5f0d976.js)。这些资源仅供接口字段核对，程序界面全部原生实现。

## 最终验证结果

- 最终全量 697 项测试通过，318.939 秒。分类与筛选专项 12 项、订单与图片专项 11 项通过；AD 实际字段与 KiCad 符号可见性回归通过。
- 最终冻结 EXE 完整流程通过，6.33 秒：原生分类与参数范围筛选、四列下载列表、购物车和订单图片、原位订单明细、导入器件、批量加购、数量递增和单价、外部购物车跳转、退出清空。所有账号及购物操作均为隔离合成服务。
- AD 独立读取器检查 8 份实际落盘 SchLib、12 个元件记录：Designator 和 Comment 可见且位置分离；KiCad 实际库中两个符号的 Reference / Value 均可见。未操作 AD/KiCad 本体进行实机放置。
- 逐项检查原生交互、亮色/暗色主题、13/17/20 字号、可调整列宽和拖动条居中。大字号筛选区域可滚动，价格字段不会被压缩截断。
- 隔离 LOCALAPPDATA、系统 PATH 与空工作目录验证通过，EXE 旁与当前目录干净；日志打包、清除后继续写入和既有崩溃诊断全量回归通过。日志含阶段、关联标识、耗时、数量与错误，不含关键词、筛选值、登录凭据或订单正文。
- EXE 内 82 个包模块、36 个资源与最终工作区一致，不包含 CAD 内核。EXE 大小 148,647,577 字节。固定入口与版本目录同步 EXE、源码 ZIP、使用说明、验证记录及校验和。
