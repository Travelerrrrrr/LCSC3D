# 日志覆盖审查（2.3.0-demo.4）

## 2.4.3 表格与分页体验

新增 `pagination.requested`，仅记录来源（商品或订单）、目标页、原页和总页数。搜索和订单继续通过已有后台任务执行，失败保留请求诊断、异常链、耗时及界面回调错误捕捉。商品简介在内存中按纯文本绘制，不写入日志，不增加逐行联网请求。

沿用隔离用户目录验证分页、取消、跨页勾选、空结果与边界页，并检查设置诊断 ZIP、日志清除后继续写入和原生崩溃捕捉；不读取真实登录凭据。具体验证结果见 [2.4.3 验证记录](2.4.3验证记录.md)。

## 2026-10-14 故障恢复补充

运行标记类型错误、无效 PID 与深度损坏现在记录 `application.marker_read_failed`；历史崩溃文件被占用或扫描失败时记录 `application.crash_cleanup_failed`，跳过已消失的文件与链接，继续建立本次运行的崩溃捕获。下载批次级异常记录 `download.batch_failed`，附带操作关联、原因链与代码位置，并向界面交付完整结果；备份内容删除后的辅助信息清理失败记录 `backup.clear_cleanup_failed`。这些事件均不记录原始配置、会话、路径或接口正文。

配置与消息 JSON 损坏、时间戳越界、gzip 损坏和过大响应复用各自读取或请求失败日志；参数范围错误保留 `catalog.range_rejected`。备份元数据无法识别时仍作为不可恢复的错误条目显示，文件清理失败与恢复冲突保留原有日志。

最终 746 项全量回归及 42 项日志诊断专项通过。真实 EXE 的设置、商城采购和进度验收均确认诊断打包、清除后继续写入；隔离子进程验证清除后仍可捕获原生崩溃。真实跨盘更新核对六个安装阶段及父操作关联。详情见 [全面缺陷排查](2026-10-14全面缺陷排查.md)。

## 2026-10-14 商城筛选与分类分页

- `catalog.matching_selected` 记录本次可勾选的匹配项数量及上下界是否填写，不记录文字搜索、数值输入或参数值。无匹配项时保留原筛选条件。
- `catalog.category_page_normalized` 记录分类接口返回固定页码 `1` 时的请求页、返回页、页容量、结果总数与页数；仅兼容分类商品接口。关键词搜索继续校验返回页码，结果总数变化、重复页面和页面不完整继续报错并记录异常链。
- `catalog.search_page.started/finished/failed` 与商城后台任务的关联 ID、代码位置和耗时记录保留。用户授权查看的现场日志在 `search_page_products` 的页码校验处报告异常，与匿名公开接口复现一致。
- 本次验证使用隔离用户数据目录，包含日志打包、清除后继续写入、未捕获异常与原生崩溃捕获，不读取真实登录凭据。实际 EXE 的设置与日志自测另核对诊断 ZIP 的范围和内容。

## 2.4.1 商城补充审查

- 数据手册：`catalog.datasheet_resolved` 记录器件编号与是否取得链接，不写资料 URL。
- 加购：`cart.batch.started`、`cart.batch_item`、`cart.batch_completed` 记录批次请求数、逐项编号/数量/序号、是否尝试写入、结果分类、错误码及停止原因，关联原有操作 ID。`cart.batch_presented` 确认结果已经送达界面。成功、明确拒绝、结果未确认与未发送分别统计，取消和意外异常保留已完成项目。
- 拒绝诊断：`cart.response_rejected` 记录业务错误码、预定义原因分类、分类来源和是否有响应消息；异常链补充 `commerce_reason` / `commerce_stage`。未知响应保留错误码，不把 402 固定解释为停售，不保存任意服务端原文。`cart.partial_response` 区分部分成功标记，`cart.batch_preflight_failed` 捕捉账号校验失败。
- 购买规则：`cart.purchase_rules` 记录所选器件核实到的起订量、递增量、是否停售及规则是否完整；规则查询失败只跳过当前器件，不能确认时不发送加购。
- 原生表格：`cart.read`、`cart.loaded`、`cart.quantity`、`cart.remove`、`orders.read`、`orders.loaded` 覆盖读取、数量保存、移除及分页加载；`store.context_menu` 只记录范围数量。
- 外部购物车：`commerce.external_open` 记录打开类型和成功/失败，浏览器未打开时有重试提示；已删除后台结算接口调用。`store.purchase_quantity` 记录数量及递增量，数量保存失败继续由 `cart.quantity.failed` 与请求诊断捕捉。价格区间匹配在内存中完成，不增加网络调用。
- 边界：日志不写 Cookie、请求表单、购物车键、订单编号/正文、收货地址、金额明细或支付信息。只通过明确的原生字段显示订单，不收集到诊断包。删除已无对应组件的网页日志路径。
- 验证：使用合成账号与本地服务注入写失败，核对单项 402 后继续、未知结果停止、部分成功保留、登录中途失效、规则查询失败、无自动重试、无结算请求和日志脱敏；完整窗口流程验证日志打包、清除及清除后继续记录。既有异常钩子、崩溃捕捉、轮转及诊断文件范围保持不变。

## 订单明细、预览图与 AD 位号补充检查

- `orders.detail_read`、`orders.detail_loaded` 记录明细读取阶段、错误及商品数量；`orders.download_import` 记录导入数量。日志不写订单编号、订单标识、购买明细、金额、收货信息或接口正文。
- `image.thumbnails` 记录批次数量，图片加载失败和解码失败分别记录 `image.thumbnail_failed`、`image.thumbnail_decode_failed`。后台图片任务保留操作上下文，不记录 URL 或响应内容；失败保留占位，不自动循环重试。
- `export.schlib_designator` 记录器件编号和位号可见状态，复用符号导出、合并和追加操作日志以及错误/取消捕捉。
- 隔离账号与本地服务检查明细失败重试、返回取消、退出清空及日志脱敏；成品流程继续检查诊断打包、清除后写入与异常诊断。

本版发现并修复的缺口：KiCad `build_library` 捕获转换错误后只返回文字，没有对应错误日志；文件替换没有独立恢复阶段记录；导出计划和 KiCad 模式切换记录不完整。现在未知图元等错误的原因链附带 `eda_code`、`eda_domain`、`eda_primitive`、`eda_source_id`，与器件/格式/阶段一起定位问题。仍禁止把任意异常正文写入日志。

日志和相关元数据不记录密码、Cookie、验证码、请求正文、代理地址、完整 URL、原始器件 JSON 或模型。结构化异常仅允许限定字符与长度的诊断字段；原因链保留异常类型、代码位置和系统错误码。诊断 ZIP 中的崩溃栈可能包含程序文件路径，但不含局部变量。

验证包括 `test_logging_diagnostics.py`、`test_log_support.py`、`test_settings.py`，以及最终 EXE 的设置/日志自测。独立子进程实际触发原生崩溃，确认清理日志后仍留下崩溃栈与异常退出标记。详细结果和材料路径见 [本版验证记录](2.3.0-demo.4验证记录.md)。

边界：日志等级会过滤低等级事件；`.finished` 表示函数返回，业务是否成功应看逐格式和批次结果。断电、强制终止等无法保证写出最后一条事件，运行标记用于后续识别非正常退出；不宣称能捕获所有系统级故障。
