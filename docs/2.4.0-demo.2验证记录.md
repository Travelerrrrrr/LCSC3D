# 2.4.0-demo.2 模型原点修复验证

2026-10-12，本地交付；未推送或发布。用户报告 C2861386 在嘉立创EDA标准版放入 PCB 后 3D 正常，但 LCSC3D 提示明显偏移。

## 原因及修复

公开 JSON 中，C2861386 的封装原点为 `(4000,3000)`，模型外框也位于该坐标系，`c_origin` 却仍为 `(400.2048,300.4208)`。旧程序直接相减，得到 `(-914.3479808,+685.6931168) mm`，既产生告警，也会写入错误模型位置。

标准版编辑器在移动/放置封装时执行 `F.g → hn.svg.moveOutline`，按模型自身外框的 `getBBox` 中心和移动量重写原点；之后查看器才使用更新的参数。demo.1 只实现后半段，遗漏前置坐标更新。demo.2 在来源适配器中补齐该步骤，原始字段保留在扩展中，不改变角度、高度和尺寸。

支持已核对的 polyline/polygon 外框和分组；不采用焊盘中心，不把有意偏置的模型强制归零。没有外框或遇到尚未支持的图元、子变换时保留原始参数及异常检查。来源四位小数网格内的差异视为舍入，不改变原字段。处理为轻量的外框坐标运算，不增加 STEP 网格化或 CAD 子进程。

## 官方脚本及用户观察

静态核对 [标准版 6.5.57 main.min.js](https://lceda.cn/editor/6.5.57/js/main.min.js)，SHA-256 `dff062e106bd6fbc8cc8c731e761555d85c1e298600cab16b0fa8514ca22a4fc`。从原文件提取 `moveOutline` 函数，在隔离 Chromium SVG 中受控回放，使用原生 `getBBox` 及明确的辅助函数替身。它验证该函数的坐标更新行为，不等同于运行整个编辑器。C2861386 的完整编辑器放入 PCB 后正常，由用户实际验证。

| 元件 | 旧 c_origin | 官方函数回放后的局部 XY（mm） |
|---|---|---|
| C2861386 / TLV75718PDRVR | 400.2048,300.4208 | 0,0 |
| C57113 / MMST5401 | 400,299.5 | 0,0 |
| C83790 / BSS138LT3G | 608,-320 | 0.0000254,-0.0000254 |

导入器与原生 SVG 浮点回放的差异小于 0.0001 mm。后两者与 C2861386 同类，demo.1 文档中的“疑似官方放置错误”已更正。

公开回归样本为 `app/tests/fixtures/model_origin_cases.json`，移除账号/所有者/状态字段，保留符号、封装与来源许可。原始响应、模型、诊断、受控回放及构建材料位于已忽略的 `work/placement-c2861386/`，配置、日志、缓存与临时文件使用隔离应用数据目录。

## 验证结果

31 项模型回归通过，包含三个真实旧原点样本、C2861386 最终矩阵及 KiCad 偏移、合法非零模型偏置、多个外框子图元、未知外框不猜测，以及原有缩放/几何核对/内嵌/合并/追加/取消回归。

612 项全量回归通过（235.602 秒），随后重新构建固定入口 `outputs/LCSC3D.exe`。此前旧 IR 回归要求“无任何诊断”，已改为对 C57113、C83790 明确要求原点更新的信息级诊断；符号/封装二维几何与往返检查继续通过。

C2861386 的真实 STEP/OBJ 经 AD、KiCad 内嵌和外部模型三种导出均成功且无模型警告。KiCad 8.0.9、9.0.9、10.0.7 原生读取/回写确认 XY 偏移为 `(0,0)`，内嵌或外部 STEP 的内容摘要与官方文件一致。AD 独立解码原生 Body 并读取内嵌 STEP，核对变换后的模型基准点回到封装原点；这不等于 AD 客户端整板验收，后者仍沿用此前的验证边界。

最终 2.4.0-demo.2 EXE 在隔离配置、仅有 Windows 系统 PATH 下，通过公开接口实际导出 C2861386、C57113、C83790。三个元件均成功，只有原点更新的信息诊断，没有偏移警告。独立核对成品生成的三个 PcbLib 中内嵌模型与放置坐标。

EXE 中 58 个应用模块、58 个资源文件及 72 个 CAD 本机库与工作区/锁定依赖一致。源码 ZIP、使用说明、验证记录和 SHA-256 清单同步更新至 `outputs/`，源码包逐文件核对。

此前受影响的库需要普通导出或重新合并生成。追加模式保留旧条目，不能自动修复已有错误模型位置。
