# 2026-10-14 全面缺陷排查与修复

本次以 `21880b3` 为基线，对配置与启动、商城搜索与筛选、收藏与采购、下载队列、AD / KiCad 导出、3D 资源与预览、更新、备份、消息记录、日志与诊断进行多轮检查。修复以可复现故障或明确代码证据为依据，并为每类问题补充回归。应用版本标识保留为 2.4.2。

## 修复的问题

| 范围 | 故障与修复后的行为 |
| --- | --- |
| Windows 文件名 | 带扩展名、设备名后有空格或含上标数字的保留名，以及截断后以空格或句点结尾的名称，可能导致导出失败。自动名称现在避开设备名并重新清理尾部；AD / KiCad 自定义库名在导出前拒绝这些输入。 |
| 参数筛选 | 极端指数可触发 Decimal 异常或下溢，空范围、倒置范围及缺失端点的区间也会被误判。现在验证数值与完整区间，错误输入保留原有选择并显示提示。 |
| EDA 数值 | 超大指数会在坐标校验中抛出非领域异常，极小指数可放大固定小数文本。现在返回明确的领域错误，同时保留正常模型旋转产生的近零项与小数精度。 |
| 网络资源 | 元件资源读取没有整体大小限制，商城 gzip 在完整解压后才检查长度。现在分块限制响应与解压结果，元件资源上限 64 MiB，保留商城原有响应上限；截断 gzip 转为可恢复的下载错误，镜像回退与连接释放继续工作。 |
| 下载取消 | 在读到响应末尾时发生取消，仍可能返回成功资源。现在在返回前再次核对取消状态。 |
| 崩溃捕获初始化 | 运行标记的 JSON 类型错误、嵌套过深或无效 PID 会中断初始化。现在逐条记录诊断并继续建立本次运行的标记与崩溃文件。 |
| 历史崩溃文件清理 | 旧文件被占用或在扫描中消失时，清理异常会阻止本次崩溃捕获。现在隔离历史文件的扫描与删除失败，跳过链接，保留本次捕获能力。 |
| 配置与消息记录 | 深度损坏的 JSON 会阻断读取；消息时间戳可能无法转换为本地时间，导致消息页异常。现在恢复为可用的空状态或默认配置，保留诊断，后续消息仍可保存与显示。 |
| 更新记录 | 合法 JSON 中的数组等错误结构会中断启动确认或后续暂存清理。现在忽略无效确认，保留失败更新备份，并继续处理其他已完成更新。 |
| 备份 | 清理先删除元数据，再删除被占用的内容，会让未清除的备份无法恢复。现在先删除内容；失败时保留完整元数据。无法显示的备份时间戳标为损坏条目，其他备份仍可访问。 |
| 商品报价 | 详情更新为无报价时，旧价格控件仍覆盖“—”。现在移除旧控件，正确显示暂无报价。 |
| 批量收藏 | 中途登录失效时，界面仍保留旧会话。现在停止后续写入、清除失效状态，并呈现此前成功项与失败提示。 |
| 国际商城分页 | 总数仍包含商品的空页被当作没有结果。现在报告分页不完整，提示重试。 |
| 下载批次异常 | 批次级异常可能没有完成结果，界面仅恢复按钮而未呈现准确结论。现在始终完成结果通知，保留已提交文件，区分部分完成、失败与取消，并记录异常原因链。 |

## 验证方法

所有日志收集、清除、配置迁移、备份恢复、登录及更新验证使用隔离的用户数据目录。账号操作使用本地模拟服务；在线部分只读取公开商品、模型和分类资料。

新增回归覆盖真实文件写入、备份文件占用、时间戳越界、深度 JSON 损坏、数值指数、已选范围保留、撤回报价、批量会话失效、批次级异常，以及普通 / gzip / 拼接 gzip / 截断响应、精确长度边界、取消与连接复用。gzip 测试同时检查内存峰值，避免只在完整解压后拒绝过大的数据。

静态检查覆盖未定义名称、错误导出、重复定义、错误常量比较、finally 控制流和循环变量覆盖等严重问题；循环闭包提示逐项检查，生产代码中的相关闭包均在本次循环内同步调用，没有发现延迟绑定故障。

日志专项检查包括异常类型、原因链、代码位置、批次关联、敏感信息排除、诊断 ZIP 白名单、清除后继续写日志，以及原生崩溃捕获。新增 `application.marker_read_failed`、`application.crash_cleanup_failed`、`download.batch_failed` 和 `backup.clear_cleanup_failed` 事件用于区分恢复阶段；事件不记录原始配置、会话或接口正文。
