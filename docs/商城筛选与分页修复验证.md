# 商城筛选与分类分页修复验证

验证日期：2026-10-14。基于 2.4.2 完成本地修复，未创建新的版本标签或发布 GitHub Release。

## 修复内容与原因

- “勾选匹配项”此前共用手动参数选择的处理逻辑，将范围条件和输入一起清除，导致范围外选项重新显示。现在把批量勾选后的列表范围作为界面状态保留，搜索文字、最小值、最大值、单位和匹配结果继续可用；异步刷新和分组切换也保留范围。应用筛选使用实际勾选值，避免保留的输入把离散选择重新覆盖为整个范围。修改范围或再次选用范围会提交新的范围，清除和重置仍可清空。
- 分类接口按请求返回了不同页的商品，却始终报告 `currePage=1`。此前第 2 个软件页面需要读取第 2 个接口页面，在严格页码校验处失败。现在只在分类接口返回固定页码 `1` 时使用请求页码；关键词搜索的页码校验、总数和容量校验、重复页面检测、空页与不完整页面保护继续生效。
- 用户授权查看的现场日志中，分类第 2 页请求在 `search_page_products` 的页码校验处失败；匿名公开接口的第 1、2、3 页分别返回不同商品并报告页码 `1`，复现与现场日志一致。

## 回归覆盖

专项回归新增用例先在旧实现上复现范围清空和分类下一页失败，再验证修复后的行为：

- 有效范围结合文字搜索、重复批量勾选、异步选项刷新、分组切换、手动取消部分勾选、离散参数提交、修改范围、清除和重置。
- 保留未提交的范围输入，不勾选禁用或隐藏选项；没有匹配项时保留原范围与条件。
- 分类与范围条件从第 1 页翻到第 2、3、末页，再返回上一页；核对商品顺序、末页数量和跨页勾选。
- 非法分页字段、关键词搜索页码不符、分类重复记录和结果总数变化继续产生错误。

`test_catalog_filters.py` 的 22 项专项测试通过。`app/build.ps1` 在隔离用户数据和临时目录运行全量回归，721 项测试全部通过，耗时 296.884 秒。

公开商城实测分别检查普通分类、范围条件、批量勾选参数和关键词结合分类。四种情形均能读取第 1、2、3、74、75 页；每页 20 项，结果总数为接口提供的 1,500 项。检查使用匿名内存会话。

## 日志与诊断

- `catalog.matching_selected` 提供匹配项数量及上下界是否填写；`catalog.category_page_normalized` 提供请求页、接口返回页、页容量、总数和页数。两者不记录文字搜索、具体范围输入或参数值。
- 原有搜索操作、耗时、异常原因链与代码位置日志保留。全量测试覆盖日志脱敏、关联 ID、错误记录、未捕获异常、诊断 ZIP 的文件范围、清除后继续写入和实际原生崩溃捕获。
- 日志收集和清除、EXE 自测使用隔离的 `LOCALAPPDATA`，不读取真实登录凭据。运行材料保存在已忽略的 `work/catalog-fix-20261014/`。

## 本地交付

最终交付入口为 `outputs/LCSC3D.exe`，并同步源码 ZIP、使用说明和 SHA-256。构建后核对成品中的 85 个应用模块和 36 项资源与工作区一致。实际 EXE 验收结果如下：

| 验收 | 结果 | 耗时 |
| --- | --- | --- |
| 匿名在线商城 | 分类、范围与勾选参数的下一页/上一页；批量勾选保留输入、查找文字和异步刷新后的匹配项；精确器件搜索恢复 | 16.17 秒 |
| 设置与日志 | 诊断 ZIP 范围与内容、清除后继续记录、清除后崩溃捕获及应用数据目录 | 69.66 秒 |
| 离线商城 | 本地合成数据的分页、跨页勾选、账号收藏与原有商城功能 | 9.78 秒 |

三项验收均成功。每项从独立 EXE 副本和工作目录运行，移除 Python/Qt 环境变量并只使用系统 PATH；核对 EXE 目录只包含 EXE，工作目录未产生文件，运行材料位于隔离的应用数据目录。验收后的副本与交付 EXE 校验一致。
