# LCSC3D 2.1.1 日志覆盖与排查

日志位置：`%LOCALAPPDATA%/LCSC3D/logs`。设置中默认 Debug。主程序与独立更新助手分别写入 `LCSC3D.log` 和 `LCSC3D-update.log`，每个文件约 2 MiB，各保留 3 份轮转备份。

## 用户如何反馈

1. 在设置中保存 Debug 等级，然后复现问题。
2. 点击“打包日志”。完成后自动打开 `%LOCALAPPDATA%/LCSC3D/diagnostics/`，将本次生成的 `LCSC3D-logs-时间-编号.zip` 发给开发者。
3. 同时附上发生时间、复现步骤、完整报错截图；元件问题附 C 编号和格式，网络问题说明代理/VPN 及浏览器访问情况。

ZIP 包含日志目录中的主程序、更新助手、轮转、崩溃日志及经过字段筛选的运行状态标记，另附反馈说明与 `diagnostics.json`。诊断信息记录收集时间、应用/系统/Python/Qt 版本、当前生效的两个代理模式、日志等级、日志写入状态及收集清单，不包含账号、完整配置、代理地址或环境变量。打包只收集直接位于日志目录下的规定文件，不递归收集，不跟随链接，不读取登录会话、下载文件或以前的 ZIP。

日志打包前先刷新并取得快照，再在后台压缩。每个文件最多取最近 8 MiB，日志内容总量最多 32 MiB、最多 128 个文件；过大、被占用或损坏的文件在 `issues` 中标明，界面提示部分收集。已生成 ZIP 不自动删除。

“清除日志”先弹出确认，清除当前/历史日志后立即继续记录，保留当前崩溃捕获句柄及运行状态标记，避免误报异常退出。已生成 ZIP、设置、登录会话和下载文件保留。无法清除的文件显示数量，不会把部分失败提示为全部成功。

## 覆盖范围

| 功能 | 关键事件前缀与信息 |
| --- | --- |
| 启动、退出、运行环境 | `application.*`；版本、Python/Qt/Windows、进程/线程、未捕获异常、上次非正常退出。 |
| 设置、配置迁移、日志目录 | `settings.*`、`navigation.*`；读取、保存、迁移、默认值、失败位置和日志写入健康状态。 |
| 日志打包和清除 | `logs.*`；收集结果、读取/打包失败、清除数量与占用文件，当前日志及崩溃捕获继续工作。 |
| 输入、队列、勾选、删除与导入 | `queue.*`；操作、数量、非法编号数量及拒绝原因，不记录原始输入。 |
| 型号查询、元件资源 | `component.*`、`resources.*`；元件编号、官方站点、HTTP 状态、缓存、镜像回退和错误。 |
| 登录、短信、扫码与图片验证 | `login.*`、`store.*`；请求步骤、服务代码、加密初始化、验证结果，图片验证要求不作为系统故障。 |
| 会话文件与恢复 | `session.*`；加密、保存、加载、过期或损坏、清除、DPAPI/文件错误。 |
| 搜索、资料、收藏、商品图片 | `catalog.*`、`favorites.*`、`image.*`；分页数量、收藏变更、元件编号、图片序号、图片解码失败。 |
| 下载、停止、格式选择 | `download.*`；批次、元件、格式、结果、部分成功、取消及失败阶段。 |
| STEP/OBJ 写入、SchLib/PcbLib 导出 | `export.*`、`file.*`；转换和写入分别记录，保留原始错误类别、系统码和代码栈。 |
| 3D、符号与封装预览 | `preview.*`、`model.*`；载入、解析、显示状态、旧响应丢弃、WebGL 初始化/着色器/上下文丢失、脚本错误类别、渲染进程退出码。 |
| 自更新全过程 | `update.*`；版本检查、下载、大小/校验和匹配、等待退出、备份、替换、启动确认、回滚和清理。 |

启动后台检查使用 `update.startup_check_started` / `update.startup_check_result`，结果区分 `available`、`latest`、`failed` 和 `cancelled`。后台失败只写 `update.startup_check_failed` 及请求原因链，不弹窗；发现新版提示记录 `update.startup_notification_shown`。手动检查和关闭会取消尚未展示的启动提醒。

## 如何定位

1. 根据用户复现时间找到 `ERROR` / `CRITICAL`，同时查看临近 `WARNING`。
2. 按 `root_id` 查同一功能操作，按 `operation_id` 和 `parent_id` 查子步骤；更新助手通过更新计划延续根操作编号。
3. 查看 `event`、`stage`、`part`、`format`。例如 `download.format_failed` + `stage=write` 表示文件写入失败，`stage=convert` 表示格式转换失败。
4. 在 `causes` 中查原始异常原因链；`errno`、`winerror`、`service_code`、HTTP 状态、JSON 行列等提供具体分类。`frames` 包含文件名、函数和行号，直接对应这版源码。`error_id` 用于关联同一异常的传播记录。
5. `*.finished` 表示操作返回，不自动等于全部成功；以 `download.part_result`、`download.batch_result`、`update.install_result` 等具体结果为准。取消、无模型、图片验证、旧响应丢弃都有单独事件。

默认 Debug 提供完整阶段。提高日志等级后会过滤较低级别步骤，但 Error 记录本身仍包含操作上下文、代码位置、原因链和可用的数字错误码。不要在发生问题后才切换 Debug 并期望补回之前的记录，应切换后重新复现。

## 隐私和边界

日志只使用明确选择的诊断字段；不写账号密码、Cookie、短信验证码、授权码、请求头/正文、服务器响应正文、完整 URL、异常原文或局部变量。错误信息中的 URL 和本机完整路径不直接写入结构化日志。

Python 与线程未捕获异常统一记录；Qt 和脚本输出只记录类别、行号及固定诊断代码。主程序还启用线程栈崩溃捕获，产生的 `LCSC3D-crash-*.log` 可能包含运行时源码文件路径，不含局部变量。正常退出会删除空崩溃文件。强制终止、断电和磁盘不可写时，应用可能来不及写入最终失败记录；上次异常退出标记只说明未正常完成退出，不能单独证明崩溃原因。

## 验证方式

`app/tests/test_logging_diagnostics.py` 注入网络截断、文件权限失败、单格式转换失败、解析失败、预览进程退出、配置/会话损坏、更新完整性失败及启动失败回滚。测试检查日志是否包含功能、元件/格式、失败阶段、原因链和代码位置，验证线程及更新助手的关联关系，并检查合成凭据不进入日志。正常登录、图片验证、取消、日志等级与轮转也有回归。

`app/tests/test_log_support.py` 核对 ZIP 文件范围、凭据和私人配置排除、文件大小限制、损坏/不可读文件、写入失败清理、链接跳过，以及清除后继续写入和崩溃捕获。设置窗口回归核对打包中关闭、失败后恢复按钮、清除确认及取消；`--self-test-settings` 在真实 EXE 中验证 ZIP 和清除流程。
