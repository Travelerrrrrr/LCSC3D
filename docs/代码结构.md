# 应用代码结构

Python 应用实现位于 `app/lcsc3d/`，使用显式包导入。`app/main.py` 是源码启动入口，`app/launcher.py` 是便携 EXE 引导入口，均不承载业务实现。静态资源、Windows 版本文件和构建规格保留在 `app/`，测试位于 `app/tests/`。

```text
app/
├── main.py                  # 源码启动入口
├── launcher.py              # EXE 启动、异常与更新助手入口
├── LCSC3D.spec
├── lcsc3d/
│   ├── core/                # 路径、资源根目录、日志、偏好、语言
│   ├── services/            # 下载、商城、会话、更新、备份、通知记录
│   ├── eda/                 # 官方数据导入、IR、AD/KiCad 与库文件写入
│   ├── models/              # 模型资源、放置基准及旋转变换
│   ├── ui/                  # 主界面、消息、设置、预览与公共控件
│   └── selftests/           # 实际 EXE 的离线验收与截图流程
├── tests/
├── assets/
├── licenses/
├── viewer.html
└── vector_viewer.html
```

开发启动仍为 `python app/main.py`；全量回归仍为 `python -m unittest discover -s app/tests`。内部导入使用 `from lcsc3d.services import backend`、`from lcsc3d.ui.main import MainWindow` 等完整包路径；不增加旧扁平模块别名或运行时搜索目录来掩盖错误导入。新增功能归入对应目录，两个启动入口保持简短。

资源根目录由 `lcsc3d/core/assets.py` 统一确定，源码运行指向 `app/`，冻结程序使用 PyInstaller 的资源根目录。样式、图标、HTML、语言和赞助二维码路径不依赖当前工作目录。应用自行生成的数据仍位于 LOCALAPPDATA 下，调整源代码目录不改变用户数据位置。

`verify_bundle.py` 递归比较包中所有模块（包括包初始化文件）与 EXE 的 PYZ，并检查静态资源和源码 ZIP。版本源为 `app/lcsc3d/ui/main.py` 的 VERSION 与 `app/version_info.txt`；发行工作流、更新验证和交付脚本读取新路径。

2.4.1 的采购功能分为 `services/commerce.py`（购物车/订单解析、递增量与数量校验、批量加购结果分类）、`ui/commerce_actions.py`（后台请求、右键动作和逐项结果展示）、`ui/commerce.py`（原生购物车/订单表格、按递增量输入与价格区间控件）。商城不创建 WebEngine 页面，不提供单独的数量页面；“跳转到购物车”只打开系统浏览器的官方购物车页面。`selftests/commerce_selftest.py` 与 `scripts/verify_commerce_delivery.py` 使用隔离目录和本地模拟服务验证成品，不接触真实账号或创建真实订单。

订单明细由 `services/order_details.py` 从官方订单详情响应中提取商品与金额，`ui/order_details.py` 在 OrdersPanel 的内容堆叠控件内展示；返回和重新查询取消旧请求。购物车复用 `store_images.py` 的并发图片加载与共享缓存，仅加载可见行。AD 位号可见性在统一的 `eda/altium_ir.py` 适配器中设置，覆盖各类 SchLib 导出路径。
